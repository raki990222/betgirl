# betgirl 투명성 로드맵

> 취지: betman·폴리마켓의 공통 약점은 **정산이 불투명**하다는 것. betgirl은 "믿어달라"가 아니라
> "누구나 검증할 수 있다"를 상품으로 만든다. 아래 단계는 그 주장을 기술적으로 완성해가는 순서다.

## 0단계 — 완료 ✅

| 항목 | 상태 |
|------|------|
| 추가 전용 원장 + SHA-256 해시 체인 (수정·삭제 DB 거부) | ✅ |
| 방문자 브라우저에서 전체 체인 재계산 검증 | ✅ |
| 픽 시각 서버 기록·경기 시작 후 등록 차단·배당 서버 채움 | ✅ |
| 경기 단위 일괄 정산 (선택적 정산 불가) | ✅ |
| 참가자별 소지금 내역 공개 (지급·베팅·정산 전액 추적) | ✅ |
| 경기 결과 보드 상시 노출 + 확정 결과 수정 불가 (008) | ✅ |

## 1단계 — 체인 앵커링 (최우선 권장)

**문제**: 현재 체계는 "운영자가 기록을 *몰래* 못 고친다"까지 보장한다. 그러나 DB 관리자가
원장을 통째로 지우고 다시 쌓으면 체인은 다시 유효해진다. "운영자 자신도 과거를 못 바꾼다"를
증명하려면 체인의 최종 해시를 betgirl이 지울 수 없는 **외부 장소에 주기적으로 게시**해야 한다.

**구현**: 하루 1회(또는 정산 직후) 베팅·정산 체인의 tip 해시 + 행 개수 + 타임스탬프를 외부에 기록.
검증 페이지에서 "이 시점의 앵커와 현재 체인이 일치한다"를 자동 대조.

**필요한 결정/정보**:
- [ ] 앵커 채널: 공개 GitHub 저장소(커밋 히스토리가 앵커) 권장. X(트위터) 계정 병행 여부?
- [ ] GitHub 계정/저장소: raki990222 계정에 공개 레포 하나 (예: `betgirl-anchor`)
- [ ] 실행 주체: 이 맥 launchd(기존 dailycrawl 패턴) vs GitHub Actions cron — 맥 실행 권장(토큰 관리 단순)
- [ ] 주기: 매일 1회 + 정산 발생 시 추가?

## 2단계 — 정산 증빙 필수화

**문제**: 정산 시 결과 증빙 URL이 현재 선택 사항. "모든 정산에는 공식 결과 링크가 붙어 있다"고
말할 수 있어야 한다.

**구현**: settle RPC에서 proof_url 없으면 거부 + 원장·보드에 증빙 링크 항상 노출.

**필요한 결정/정보**:
- [ ] 증빙 형태: 공식 결과 페이지 URL만? 캡처 이미지도? (이미지면 Supabase Storage 버킷 신설 필요)
- [ ] KBO 결과의 표준 출처 확정 (koreabaseball.com 경기 결과 페이지 URL 규칙)

## 3단계 — 정산 SLA 지표 공개

**구현**: 경기 시작~결과 확정까지 걸린 시간을 경기마다 기록(008의 result_at으로 이미 측정 가능),
원장 상단에 "평균 정산 소요 N시간 · 최장 M시간" 통계 노출.

**필요한 결정/정보**:
- [ ] 목표 SLA (예: 경기 종료 후 12시간 내 정산 — 대외 약속으로 걸 수 있는 수치)

## 4단계 — 참여 개방

**문제**: 지금은 운영자가 계정을 발급. 참가자가 늘어야 장부가 의미를 가진다.

**필요한 결정/정보**:
- [ ] 개방 시점 (법무 검토 완료 후?)
- [ ] 가입 방식: 이메일 인증 가입 / 초대 코드 / 소셜 로그인
- [ ] 가입 축하 벳 어뷰징 방어 (다계정 생성 → 무한 벳): 이메일 도메인 제한, 초대제, 지급 지연 등
- [ ] 닉네임 정책 (현재: 20자, 변경 불가)

## 5단계 — 보상 제도 연동 (법무 검토 결과 대기)

걸음 적립·기프티콘 교환이 확정되면: 적립 트랜잭션도 betgirl_credits 체계(공개·추가 전용)로 편입,
교환(차감) 기록도 동일하게 공개. **모든 벳의 발생과 소멸이 공개 원장에 남는 구조** 유지가 원칙.

**필요한 결정/정보**:
- [ ] 법무 검토 결론 (예측 베팅 + 실물 보상 조합의 허용 범위)
- [ ] 앱/잠금화면 스택 결정 (별도 프로젝트)

## 운영 원칙 (전 단계 공통)

1. 새 기능도 "공개·추가 전용·검증 가능" 3원칙을 지킨다.
2. 운영자 행위(경기 게시, 정산, 벳 지급)는 전부 공개 기록으로 남는다.
3. 원장 리셋은 실참가자 유치 전 마지막 1회만. 이후는 어떤 이유로도 하지 않는다
   (리셋 가능성 자체가 앵커링 이후에는 공개적으로 드러난다).
