# betgirl 투명성 로드맵

> 취지: betman·폴리마켓의 공통 약점은 **정산이 불투명**하다는 것. betgirl은 "믿어달라"가 아니라
> "누구나 검증할 수 있다"를 상품으로 만든다. 아래 단계는 그 주장을 기술적으로 완성해가는 순서다.

## 1단계 — 체인 앵커링 (최우선 권장)

**문제**: 현재 체계는 "운영자가 기록을 *몰래* 못 고친다"까지 보장한다. 그러나 DB 관리자가
원장을 통째로 지우고 다시 쌓으면 체인은 다시 유효해진다. "운영자 자신도 과거를 못 바꾼다"를
증명하려면 체인의 최종 해시를 betgirl이 지울 수 없는 **외부 장소에 주기적으로 게시**해야 한다.

**구현**: 하루 1회(또는 정산 직후) 베팅·정산 체인의 tip 해시 + 행 개수 + 타임스탬프를 외부에 기록.
검증 페이지에서 "이 시점의 앵커와 현재 체인이 일치한다"를 자동 대조.

**필요한 결정/정보**:
- [x] 앵커 채널: 공개 GitHub 저장소 + OpenTimestamps. **X 제외 확정**(커뮤니티 사본 감시로 충분, 2026-08-06)
- [x] GitHub 저장소: raki990222/betgirl-anchor (⏳ GitHub 웹에서 공개 레포 생성 대기 — 생성 즉시 자동 푸시)
- [x] 실행 주체: 이 맥 launchd `com.betgirl.anchor` (매일 12:20 KST) — scripts/anchor.py
- [x] 주기: 매일 1회 (변화 없으면 스킵, 멱등)

## 2단계 — 정산 증빙 필수화

**문제**: 정산 시 결과 증빙 URL이 현재 선택 사항. "모든 정산에는 공식 결과 링크가 붙어 있다"고
말할 수 있어야 한다.

**구현**: settle RPC에서 proof_url 없으면 거부 + 원장·보드에 증빙 링크 항상 노출.

**필요한 결정/정보**:

## 6단계 — 수익화·가차샵·등급제 (2026-08-06 요구, 일부 구현)

**구현 완료(014)**:
- 정산 수수료: 적중 픽 베팅액의 5% (정책 이력 공개·정산 행에 표시·취소 환급은 무수수료)
- 상품 교환소 /shop: 카탈로그·신청(가격 서버 복사)·유예 7일 고지
- **광고 수익 공개 원장**: 수익(현금)과 상품 지급(현금 원가)의 대차를 누구나 확인 —
  "상품을 나눠줘도 마이너스가 아닌지"가 공개 지표

**설계만 (구현 전 법무 확인 필수)**:
- 🔴 **가차샵 확률형 교환**: 100% 확률=100pt(천장) / 50%=55~60pt / 10%=12~15pt 티어.
  공정성은 커밋-리빌(사전 해시 공개 → 결과 공개) 방식으로 원장 체계에 편입 가능.
  ⚠️ 확률형 + 실물 상품 = 사행성·확률 고지 규제 영역. 포인트 전용이라도 법무 서면 확인 후 구현.
- 🔴 **복합 결제(포인트+현금/카드)**: 현금이 유입되는 순간 "현금→포인트→베팅→상품" 경로가 생겨
  현행 방어선("현금→벳 불가" 고지)이 무너짐. **유사 스포츠토토/도박개장 리스크 직결 — 법무 승인 전
  구현 불가 항목으로 분류.**
- 🔴 **상위 랭커 정보 유료 열람**: (a) 원장이 공개인 이상 유료화가 모델과 모순 (b) "유료 정보를
  판매하지 않습니다" 고지와 정면 충돌 (c) 베팅 정보 유료 판매 규제 영역. 대안 = 랭커 **베네핏**
  (등급 페이백·전용 상품)은 가능.
- **등급제·페이백**: 누적 베팅액 기반 등급(예: 브론즈~다이아) + 등급별 정산 수수료 할인(페이백).
  수수료 체계가 생겼으므로 "등급별 수수료율"로 자연스럽게 구현 가능 — 파라미터 확정 대기.
- **참여형 광고 리워드(오퍼월)**: 버즈빌·애드팝콘 등 공급사 계약 필요. 계약되면 적립은
  credits INSERT 한 줄(reason='광고 참여 리워드')로 원장 편입 완료 상태.
